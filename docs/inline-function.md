# Inline function

`inline_func()` with the cursor on the function, at its definition or at any
call. kotlin-lsp finds the calls (in any file) and refactoring.nvim matches
them with Tree-sitter. The inlined code is generated by
the plugin's `lua/refactoring-kotlin/kotlin.lua`, IDE-style: arguments are substituted into
the body where that keeps the behaviour. When every call is inlined, the
function is deleted.

## Supported

### Function shapes

- A block body whose single `return` is the last statement (`inline_func_block_body`).
- An expression body, `fun f(x: Int) = x * 3` (`inline_func_expression_body`).
- A body without a return value (`inline_func_statement_call`).
- Statements before the `return`, including nested blocks; their indentation is kept (`inline_func_body_statements`, `inline_func_nested_blocks`).
- Top-level functions, class methods, `object` members and extension functions,
  called from any file (`inline_func_cross_file`).

### Arguments

A simple argument (a variable, a literal, `this`) is always substituted. Any
other argument is substituted only when all of these hold:

- it's the only non-simple argument of the call;
- it's used once;
- the function has nothing but its return value;
- that use isn't conditional (`&&`, `||`, `?:`, `if`, `when`, `try` or a lambda).

Otherwise it's declared as a `val`, so it still runs once and in the same
order. An unused argument is dropped, or kept as a statement if it contains a
call. Named arguments are matched by name in any order, an omitted argument
takes the parameter's default value, and arguments can span several lines.
Parentheses are only added where operator precedence needs them. Case
`inline_func_arguments`, with `fun addTax(price: Int, rate: Int = 2) = price * rate`
(as a block body):

```kotlin
// before                                // after
val a = addTax(base, 3)                  val a = base * 3
val b = addTax(base)                     val b = base * 2
val c = addTax(rate = 4, price = base)   val c = base * 4
val d = addTax(compute(), 3)             val d = compute() * 3
val e = addTax(compute(), compute())     val price1 = compute()
                                         val rate = compute()
                                         val e = price1 * rate
val f = addTax(base + 1)                 val f = (base + 1) * 2
addTax(price, 5)                         // removed: no side effects
```

A literal used in a string template is written into the string:
`"$label is big"` with `label = "item"` becomes `"item is big"`
(`inline_func_local_renames`).

A lambda argument, including a trailing lambda (`f(x) { ... }`, the last
argument), is always declared as a `val` with the parameter's type: without it,
Kotlin can't infer `it` (`inline_func_trailing_lambda`):

```kotlin
// fun applyTwice(value: Int, transform: (Int) -> Int): Int { return transform(transform(value)) }
val result = applyTwice(3) { it + 1 }  →  val transform: (Int) -> Int = { it + 1 }
                                          val result = transform(transform(3))
```

### Names

A `val` the inlined code introduces (for an argument or a local of the body)
gets a number when its name is already used in the calling function. That
covers several inlines in the same block too (`inline_func_local_renames`,
`inline_func_repeated_args`):

```kotlin
// fun twice(x: Int) = x + x
val b = twice(compute())     →  val x = compute()
                                val b = x + x
val c = twice(x = base + 1)  →  val x1 = base + 1
                                val c = x1 + x1
```

### Where the call is

- As a statement, `f(x)`, or as `val y = f(x)`: replaced by the body.
- Inside an expression, e.g. `println(f(x))`, `f(x) + 1`, `y = f(x)`,
  `f(x).toString()` or a lambda's last expression: the call is replaced by the
  return value, and the other statements of the body are inserted before the
  enclosing statement, in evaluation order (`inline_func_nested_calls`,
  `inline_func_nested_calls_skipped`, `inline_func_lambdas`):

```kotlin
// fun half(n: Int) = n / 2
val a = half(base + 1) * 3   →  val a = (base + 1) / 2 * 3
val d = xs.map { half(it) }  →  val d = xs.map { it / 2 }

// fun noisy(n: Int): Int { println("noisy $n"); return n + 1 }
println(noisy(base) + noisy(base * 2))
→
println("noisy $base")
val n = base * 2
println("noisy $n")
println(base + 1 + (n + 1))
```

### Method calls

The receiver is handled like an argument: substituted when it's simple, a `val`
otherwise. `this` becomes the receiver, and the class members that the body
uses without `this.` get qualified with it. These are properties, methods, and
constructor `val`/`var` parameters. Calls from inside the class (`f(x)`,
`this.f(x)`) keep the body as it is (`inline_func_method`,
`inline_func_method_nested`, `inline_func_extension`, `inline_func_object`):

```kotlin
// class Shop { var total = 0; fun fee() = 2; fun price(n: Int): Int { return this.total + n * fee() } }
val a = s.price(5)          →  val a = s.total + 5 * s.fee()
val b = getShop().price(1)  →  val shop1 = getShop()
                               val b = shop1.total + 1 * shop1.fee()
price(3) (inside Shop)      →  this.total + 3 * fee()
"hey".shout()               →  "hey".uppercase() + "!"
Utils.twice(4)              →  4 * 2
println(s.label("Hi"))      →  val text = "Hi ${s.name}"
                               println(text)
                               println(text)
```

### Layout

The inserted lines are re-indented with Neovim's indenter. Deleting the
function leaves exactly one blank line where it was (or none at the end of the
file), and a class or `object` keeps its closing brace on its own line
(`inline_func_class_member`, `inline_func_last_in_file`, `inline_func_object`).

### Calls that can't be inlined

The other calls are still inlined, but those calls are left as they are and
the **function is kept**. A one-line warning gives the reasons (tested in
`inline_func_method`, `inline_func_nested_calls_skipped`,
`inline_func_lambdas`, `inline_func_private_members`). The plugin's own
"Inlined N function occurrences" message also counts the skipped calls.

## Not supported

These calls are skipped, and the function is kept:

- **Safe calls**, `obj?.f()` (tested: `inline_func_method`). The whole call
  depends on `obj` not being null.
- **A body with statements, called where they can't be moved before the
  statement** (tested: `inline_func_nested_calls_skipped`,
  `inline_func_lambdas`): conditional code (`if (c) f(x) else 0`, `a && f(x)`,
  `x ?: f(x)`), an expression body (`fun g() = f(x)`) or a one-line lambda
  (`xs.map { f(it) }`).
- **Private or protected members used by the body, called from outside the
  class** (tested: `inline_func_private_members`). Inside the class it's inlined.

These functions aren't inlined at all:

- **More than one `return`**, e.g. an early return (tested:
  `inline_func_early_return`). Nothing changes; the plugin reports "The function
  has multiple return statements".
- **An empty body**, `fun f() {}` (tested: `inline_func_empty_body`). The
  function isn't recognized:
  "Couldn't find the definition of the symbol under cursor using treesitter".

This falls back to upstream's output, one `val` per parameter with the body
copied as is:

- **A default value that uses another parameter** (tested:
  `inline_func_default_uses_param`). The default is lost:

  ```kotlin
  // fun area(width: Int, height: Int = width): Int { return width * height }
  val square = area(3)  →  val width = 3
                           val height = /* missing argument */
                           val square = width * height
  ```

These produce code that doesn't compile (all tested):

- **A vararg parameter** (`inline_func_vararg`). It's handled like a normal
  parameter, so it gets only the first argument: `println(sumAll(1, 2, 3))`
  becomes `println(1.sum())`.
- **The function used as a value** (`inline_func_function_reference`). A
  reference such as `::isEven` isn't a call, so it's left alone, but the function
  is deleted anyway.
- **Implicit members of an extension function's receiver**
  (`inline_func_extension_implicit_member`). Only an explicit `this` is replaced,
  so `"hi".exclaim()` with `fun String.exclaim() = uppercase() + "!"` becomes
  `uppercase() + "!"`, and the receiver is lost.
- **Inherited members** (`inline_func_inherited_member`). Only the class's own
  members are known: `dog.speak()` with `fun speak() = sound + "!"` (`sound` is
  declared in the superclass) becomes `sound + "!"`.
- **A lambda parameter with the same name as a member**
  (`inline_func_lambda_shadows_member`). It's qualified like the member:
  `factors.map { size -> size * 2 }` becomes
  `listOf(1, 2).map { box.size -> box.size * 2 }`.

These compile, but you may want to tidy them (all tested):

- **Renaming is conservative** (`inline_func_conservative_rename`). A name
  counts as taken if it appears anywhere in the calling function: the body's
  `greeting` becomes `greeting1` because a lambda further down declares its own
  `greeting`.
- **Blank lines inside the inlined body are removed**
  (`inline_func_blank_lines_in_body`).
- **A function without a return value, called inside an expression**
  (`inline_func_unit_in_expression`). The call becomes `Unit`:
  `val logged = listOf(logValue(1))` becomes `println(1)` and
  `val logged = listOf(Unit)`.
